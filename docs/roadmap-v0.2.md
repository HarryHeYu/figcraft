# Roadmap — v0.2 规划（仅规划，未实施）

本文是 v0.2 的需求拆解与优先级排序，作为 v0.1.0（Alpha）发布后的开发
依据。排序原则：先消除影响真实科研图交付的边界，再提升 Agent 反馈闭环，
最后扩展表达能力。每项标注预估规模（S ≤1 天 / M 1–3 天 / L >3 天）与
验收标准草案。**本文不是承诺时间表。**

## P0 — Figure Doctor（图形成像质量诊断器）

**问题**：当前 lint 报告的是规则命中（FC00x），用户仍需自行把 finding
翻译成修复动作；跨格式一致性、文字溢出概率、字体可用性散落在不同输出里。

**需求拆解**：
1. `papercanvas doctor PATH`（CLI）与 `papercanvas_doctor`（MCP，第 8 个
   工具）：一次运行聚合——硬校验 + FC001–FC008 + 渲染预检（字体覆盖/
   替代、三格式可导出性）+ 跨格式几何一致性抽检。
2. 输出分级：`blocking`（必须修）/ `advisory`（建议）/ `environment`
   （本机字体等环境项），复用现有 Finding 结构并新增级别字段。
3. 每条 finding 附带**建议动作**（可直接转成 patch 操作的 JSON 片段），
   例如 FC003 → `{"op": "update_node", "id": …, "w": …}` 的建议值。
4. `--format json` 机器可读；`--strict` 时 blocking 存在则退出码 1。

**验收草案**：三个示例 doctor 全绿；构造溢出/穿越/字体缺失图各一，
doctor 能给出可执行建议；MCP 与 CLI 结果一致。

规模：M。依赖：无新外部依赖。

## P1 — 单/双栏自适应布局（论文图尺寸预设）

**问题**：期刊图通常有固定物理尺寸（单栏 ~89mm、双栏 ~183mm、高度约束），
当前用户需手算画布并依赖自动布局的偶然结果。

**需求拆解**：
1. `layout --preset` 扩展：`two-column`（双栏宽 183mm）、`single-column`
   （89mm）、`--width/--height` 目标尺寸约束；字号的栏宽自适应缩放选项。
2. 尺寸约束下的折行策略：节点数过多时允许 2×N 网格排布（layered 的
   多列泛化），而不是无限横向加宽。
3. 画布重算保持"内容 + margin"契约；导出尺寸即投稿尺寸（mm 精确）。
4. FC001 语义不变；新增 advisory：建议字号 < 阈值时提示缩小内容。

**验收草案**：同一 IR 分别以 single/two-column 预设布局，宽度精确等于
目标值，lint 无 error，导出 PDF 物理尺寸正确。

规模：M–L（多列泛化是主要工作量）。依赖：无。

## P1 — 视觉反馈闭环（渲染结果的 Agent 可读验证）

**问题**：Agent 现在只能靠几何/lint 断言判断质量，"看起来对不对"缺一环。

**需求拆解**：
1. SVG→PNG 光栅化辅助（可选依赖路径：resvg/cairosvg 之一，明确可选、
   未安装时给出安装指引），仅用于验证，永不进入交付产物。
2. 基线快照回归：`papercanvas render --snapshot` 生成 PNG 基线 +
   `doctor --compare` 做像素差分（阈值 + 差异区域定位），防渲染回归。
3. 反馈给 Agent 的结构化描述：覆盖区域、变化百分比、可疑重叠区坐标——
   让 Agent 能"看到"并定向修复。
4. 不做 AI 图像理解；纯确定性像素/几何比对。

**验收草案**：改颜色/移动节点后差分定位到正确 bbox；三个示例建立基线；
CI 中快照回归在固定平台运行。

规模：M。依赖：一个光栅化后端（可选依赖，Graceful 缺失）。

## P2 — 高级路由（在 v0.1 避障之上）

**问题**：当前避障是固定候选序（原路径 → 主轴通道 → 副轴通道），复杂图
仍可能有不可绕穿越或非最短绕行。

**需求拆解**：
1. 通道候选泛化：按障碍分布生成多个候选通道（而非固定 ±6mm 两档），
   仍确定性排序（按绕行长度优先）。
2. 可选的 A*/网格搜索模式（`route: "grid"`，IR 中按边或全局可配），
   处理密集布局；默认保持现行为（兼容性）。
3. 拐角偏好参数（最少拐角 vs 最短长度）；路线长度/拐角数写入 inspect。
4. FC006 与路由共享同一搜索，保证"报的都是真不可绕"。

**验收草案**：密集棋盘场景（≥10 障碍）全边无穿越或如实报告；确定性
测试；现有 16 端口组合行为不变。

规模：M–L。依赖：无。

## P2 — 混合字体系统（同一图内多字体跑排）

**问题**：v0.1 按图选一个字体——中英混排时英文也被 CJK 字体渲染（风格
不统一），emoji 仍无法覆盖。

**需求拆解**：
1. IR 扩展（schema 0.2 提案）：`theme.font_fallbacks: [families]` 与
   节点级 `font` 覆盖；`schema_version` 读取层按"低版本可读"规则演进。
2. TextLayout 升级为**跑排（run segmentation）**：按字形单元把一行拆成
   run，每 run 用覆盖它的字体度量；渲染器按 run 分段绘制（SVG tspan /
   PDF 多 setFont / PPTX 多 run）。
3. PDF 嵌入多字体子集；跨格式一致性测试扩展到混合 run。
4. emoji：可选 Noto Emoji（TTF，monochrome）作为最后回退，仍不覆盖时
   FC007/渲染警告明示（继承 v0.1 行为）。

**验收草案**：中英混排标签在三种格式中各自以正确字体渲染且位置一致；
纯英文图与 v0.1 输出兼容（回归不变形）。

规模：L（TextLayout 是核心路径，需最谨慎的回归覆盖）。依赖：无新增
（字体仍取自系统/可选打包 OFL 字体）。

## 明确不做（v0.2 仍不做）

网页画布、AI 图像生成、位图→SVG 逆向、任意 SVG/PPTX 无损双向导入、
TikZ 编译器、PPTX→IR 反向同步、付费 AI API。

## 排序总结

| 优先级 | 项 | 规模 | 理由 |
|---|---|---|---|
| P0 | Figure Doctor | M | Agent 反馈闭环的最大杠杆，全部已有能力聚合 |
| P1 | 单/双栏自适应 | M–L | 直接决定"能不能进论文排版流程" |
| P1 | 视觉反馈闭环 | M | 质量回归的保险丝；需要引入可选光栅化依赖 |
| P2 | 高级路由 | M–L | v0.1 避障已覆盖主场景，收益递减 |
| P2 | 混合字体系统 | L | 触及核心度量路径，需 schema 0.2 演进 |
